# 数据库备份与恢复演练

本文定义 Finals Compass MySQL 数据的备份、校验、恢复演练和留存要求。演练恢复到自动创建的隔离数据库，不覆盖当前业务库。

## 创建备份

前提是 `deploy/docker-compose.yml` 中的 MySQL 已启动且 healthy，`deploy/.env` 中数据库变量正确。

```bash
./scripts/db-backup.sh
```

默认输出到被 Git 忽略的 `backups/mysql/`。脚本使用事务一致性逻辑备份，包含存储过程、触发器和事件，随后执行 gzip 完整性检查并生成 SHA-256 文件。指定备份盘可运行：

```bash
BACKUP_DIR=/mnt/finals-compass-backups ./scripts/db-backup.sh
```

备份与 `.sha256` 必须一起复制到异机或对象存储，并启用存储加密和独立凭据。推荐每日备份，保留 30 个日备和 12 个周备。

## 恢复演练

```bash
./scripts/db-restore-drill.sh backups/mysql/finals-compass-YYYYMMDDTHHMMSSZ.sql.gz
```

脚本校验压缩包，创建隔离演练库，导入备份，核对表数量、Flyway 成功迁移数和用户数，最后通过 trap 自动删除演练库。成功输出包含 `Restore drill passed`。命令输出、SHA-256、执行人和时间应保存到运维工单。

## 周期与验收

- 每月至少演练一次；Flyway 大版本迁移或生产迁移前额外演练。
- 演练使用最近 24 小时内的备份；RPO 目标 24 小时，RTO 演练目标 60 分钟。
- 连续两次失败应暂停数据库发布，排查后重新备份并复演。
- 每季度在独立环境做一次完整应用恢复，并检查 `/api/system/health`、登录、课程读取和附件索引。

真实灾难恢复属于破坏性操作，不由演练脚本执行。应先停止写流量、创建故障库快照，再由两人复核目标库名和备份校验和；恢复后执行 Flyway `validate` 和业务抽查。不得把演练脚本改成直接导入生产库。
