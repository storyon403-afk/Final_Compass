# 仓库结构与应用边界

## 总体结构

仓库采用单仓库多应用结构，将可独立运行和独立构建的应用放在 `apps`，将服务器进程放在 `services`

```text
apps/web                 Vue 主站
apps/livedoc             LiveDoc 独立前端应用
services/api             Spring Boot API
services/markitdown-worker
services/pdf-renderer
```

## 前端构建边界

`apps/web` 负责主站路由、认证界面和各业务模块入口，构建结果写入根目录 `dist`

`apps/livedoc` 负责文档编辑器及其独立依赖，构建结果写入 `dist/livedoc`

根目录工作区脚本按主站、LiveDoc 的顺序构建，主站负责清空旧产物，LiveDoc 只更新自己的子目录

开发环境中主站运行在 5173 端口，LiveDoc 运行在 5174 端口，主站通过 Vite 代理保持 `/livedoc` 同源访问

生产环境中 Nginx 直接发布组合后的 `dist`，现有 `/livedoc/ScriptoriumModules/scriptorium.html` 地址保持不变

## 后端边界

`services/api` 是业务 API 主进程，领域代码继续按课程、CET、AI、LiveDoc、身份和系统能力划分

`services/markitdown-worker` 和 `services/pdf-renderer` 是可独立部署的辅助进程，不依赖 API 的源码目录

## 数据与产物

`dist`、`target`、`node_modules`、`.venv` 和缓存目录都是可重新生成的本地产物

`uploads` 和环境变量文件属于运行数据，不应作为构建产物处理，也不得随意删除或提交
