Finals Compass AI 演进路线

本文用于记录 Finals Compass AI 当前阶段的技术路线规划。 核心目标： 从“AI功能模块”逐步演进为“面向学生学习任务的智能 Agent 平台”。

一、总体定位

Finals Compass AI 不作为通用聊天机器人存在。 它的目标是： 学生提交学习资料、问题或目标后， 系统自动理解需求， 调用对应 AI 能力， 完成具有实际价值的学习任务， 输出可以直接使用的学习成果。
用户需求 ↓ Learning Task识别 ↓ Workflow执行 ↓ Skill组合 ↓ Provider调用模型 ↓ 生成学习成果

二、当前阶段架构

用户 ↓ AI Analysis Service ↓ AiAgentOrchestrator ↓ Input Guardrail ↓ LearningTask / Intent Router ↓ Workflow ↓ Skill ↓ Provider Gateway ↓ DeepSeek / Gemini / OpenAI

当前核心模块：

  • LearningTask：描述学生目标
  • Workflow：描述完成目标的步骤
  • Skill：描述单一AI能力
  • CourseContext：提供课程、教师、资料背景
  • AiTask：记录任务执行过程

阶段一：完善 AI 工作流核心（当前）

目标：

让 Finals Compass AI 可以稳定完成真实学习任务。

主要任务：

  • 增加和完善 Skill
  • 完善 LearningTask 边界判断
  • 完善 Workflow 执行流程
  • 增加课程上下文读取能力
  • 完善 AI Task 状态记录

重点能力：

课程资料分析 ↓ 考试重点分析 ↓ 复习计划生成 ↓ 答案检查 ↓ 解题辅助

阶段一的重要原则

用户不选择 Skill。 Skill 是内部能力。 用户只表达自然语言目标。 系统自动判断： “用户想完成什么学习任务”。
例如： 用户： “帮我准备数值分析考试” 系统： 
LearningTask:
EXAM_PREPARATION

Workflow:
material-summary
        ↓
exam-focus-analysis
        ↓
study-plan-generation

阶段二：Skill 数据库化

目标：

将 Skill 从代码配置升级为平台配置能力。

当前： 
AiSkillConfiguration.java

↓

DefaultAiSkill

↓

AiSkillRegistry
未来： 
ai_skill数据库

↓

SkillLoader

↓

AiSkillRegistry

↓

Workflow

数据库保存内容：

  • Skill ID
  • Prompt(System Instruction)
  • 输出规范(Output Contract)
  • 工具权限
  • 输入限制
  • 版本信息
  • 启用状态

收益：

  • 修改Prompt无需重新部署
  • 支持后台管理Skill
  • 支持Skill版本控制
  • 方便后期扩展AI能力

阶段三：Agent Runtime + MCP Tool体系

目标：

让 AI 从固定Workflow执行， 扩展到可以调用外部环境完成复杂任务。

Agent Runtime ↓ MCP Gateway ↓ Tool Registry ↓ External Tools

新增能力：

  • 网页搜索
  • 文件处理
  • 浏览器访问
  • 用户环境交互

阶段四：用户授权浏览器 Agent

目标：

通过用户授权，让 Agent 使用用户浏览器环境获取信息。

用户Chrome浏览器 ↓ Chrome Extension ↓ WebSocket ↓ MCP Gateway ↓ Agent Runtime ↓ Skill Workflow

浏览器插件定位：

浏览器插件不是Agent本身。 它是Agent的工具执行端。 类似： Agent = 大脑 插件 = 眼睛和手 MCP = 神经接口

第一阶段支持范围：

  • 桌面 Chrome
  • Chromium内核浏览器
  • 用户主动授权
暂不考虑：
  • 手机浏览器插件
  • 所有浏览器兼容

最终目标架构

用户 | Finals Compass Web | AI Decision Layer | +-------------+-------------+ | | Learning Workflow Agent Runtime | | Skill Chain MCP Tools | | Course Database Browser / Web / File | LLM API

开发优先级

阶段 目标
当前 Workflow + Skill完善 + 边界判断
下一阶段 Skill数据库化
之后 MCP Tool体系
长期 Chrome Extension + Browser Agent

核心思想

不要先追求“万能Agent”。 先建立： 可靠的学习任务执行系统。 Agent 是未来能力扩展， 不是当前产品核心。 Finals Compass 的核心价值： 课程生态 + 教师信息 + 学习资料 + AI工作流。
