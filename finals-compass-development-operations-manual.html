2. 公共请求生命周期

2.1 浏览器启动

  1. apps/web/src/main.js 建立 Vue Router：/、/question-vine、/cet、/ai-center/**。
  2. 挂载前执行 authApi.restore() → GET /api/auth/session。HttpOnly Cookie 自动携带；Vue 内存只保存 username/displayName/role。
  3. App.vue 依据 authenticated 显示登录页或业务壳，并加载身份、公告、模块状态和未读消息。

2.2 前端 HTTP 适配器

apps/web/src/api.js::request() 是 JSON 主入口。它设置 credentials:'include'；非 GET/HEAD/OPTIONS 从 finals_compass_csrf Cookie 读取值并写 X-CSRF-Token；非 2xx 解析 JSON，401 清会话，并把响应 X-Trace-Id 拼进错误。requestBlob() 用于文件。chatApi.streamMessages() 单独处理 text/event-stream，但复用 Cookie/CSRF 规则。

2.3 Nginx 分流

  • location /：静态文件不存在时回退 /index.html。
  • /api/：反代 backend:8080，读超时 120 秒。
  • /api/ai/invoke：关闭请求缓冲，避免图像体落临时盘。
  • /ws/browser-bridge：WebSocket Upgrade，读超时 300 秒。
  • 统一返回 CSP、nosniff、SAMEORIGIN、Referrer/Permissions Policy。

2.4 Spring 固定执行顺序

  1. RequestTraceFilter.doFilter() 创建 requestId/traceId，写响应头、RequestContext attribute 和 MDC；finally 记录 method/path/status/duration 并清 MDC。
  2. AuthenticationInterceptor.preHandle() 从 Bearer 或 Cookie 取 token，调用 AuthService.authenticate() 查询 login_session JOIN app_user，把 CurrentUser 写入 request attribute。
  3. Cookie 写请求执行 validCsrf() 常量时间比较；失败 403。
  4. ModuleMaintenanceInterceptor.preHandle() 将课程/Circle、CET、AI 分别映射到模块开关；维护时普通用户 503，管理员旁路。
  5. AuthenticatedUserArgumentResolver.resolveArgument() 为 @Authenticated CurrentUser 注入身份；Jackson 与 Jakarta Validation 解析/校验 DTO。
  6. Controller 进入 Handler/Service；@Transactional 建立事务；Repository 使用 JdbcClient。
  7. ApiExceptionHandler 将校验错误变 400、业务异常保留状态、未知异常脱敏为 500，并附 traceId。

5. 问题藤完整追踪

5.1 读取

QuestionVineView.onMounted()
→ questionVineStore.loadQuestionVineTopics()
→ questionVineApi.topics()
→ QuestionVineController.topics()
→ QuestionVineService.topics()
→ QuestionVineRepository.topics() + answers(topicId)
→ question_vine_topic / question_vine_answer
→ Topic[] → store ref
→ threadedAnswers computed 以 parentAnswerId 组树 → SVG/叶片/回复树

focusRouteTopic() 支持 ?topic=uid 与 hash；搜索覆盖序号、标题、正文、类别和标签。

5.2 发布

  1. QuestionVineView.publish() → store action → questionVineApi.createTopic()。
  2. QuestionVineController.create() 用 CreateTopic 校验：标题≤100、类别≤30、标签≤3且每项≤20、正文≤5000。
  3. QuestionVineService.create() 先 ActionRateLimitService.questionTopic()，默认每用户每小时 5 次，Redis Lua 原子固定窗口。
  4. 事务内 repository.lockTopics() 执行 FOR UPDATE；nextSequence() 取 max+1；create() 写主题。匿名别名由 userId 稳定派生。
  5. 返回 201 Topic，前端刷新并滚动到新叶片。

5.3 回答、回复和通知

QuestionVineView.answer() → questionVineApi.answer(uid,content,parentId) → QuestionVineController.answer() → QuestionVineService.answer()。先执行每小时 30 次回答限流；topicOwner() 验证主题；楼中楼用 answerOwner() 确保父回答属于同一 topic。回复回答者或顶层回答作者时调用 SiteMessageService.notify()，链接回 /question-vine?topic=uid；最后 addAnswer() 写 parent_answer_id。

5.4 管理删除

DELETE /admin/topics/{sequence} → QuestionVineService.delete()：requireAdmin → 锁序号 → bySequence → answerCount → auditDelete → delete（外键级联回答）→ shiftAfter。单事务保证审计、删除、重排一致。

6. CET 完整追踪

6.1 前端状态机

CetView.vue 保存 level → mode → section → paper → item 五级状态，并用 history.state[CET_HISTORY_KEY] 支持后退。chooseMode('FULL_PAPER') 调 cetApi.papers(level)；chooseSection() 调 cetApi.items(level,mode,section)；choosePaper/openItem 初始化作答、翻译和音频。

读取链后端与数据
cetApi.papers → GET /cet/papersCetController.papers → CetQueryHandler.papers → JdbcCetQueryRepository.findPublishedPapers；查询 paper/source 并判断音频。
cetApi.items → GET /cet/itemsCetController.items → CetQueryHandler.items → findPublishedItems；联结 paper/section/item，只返回发布内容。

CetQueryHandler.level() 只接受 CET4/CET6，mode() 只接受 PRACTICE/INTENSIVE，非法值在 SQL 前返回 400。

6.2 音频

  1. openItem()/choosePaper() 先 cetApi.prepareAudioStream()，确保 Cookie 会话。
  2. 原生 <audio> 请求 /api/cet/items/{id}/audio，Cookie 自动携带，GET 无 CSRF。
  3. CetController.audio() → CetItemHandler.audio() → Repository 元数据 → UploadStorage.resolve() → Resource。
  4. prepareAudioSegment/enforceAudioSegment 用 audioStartMs/audioEndMs 限制精听区间。

6.3 管理写入

  • savePaper → CetPaperHandler.create/update → JdbcCetPaperRepository；create 同时 createSlots() 初始化练习/精听题型槽。
  • saveItem → CetItemHandler.create/update → JdbcCetItemRepository；validate 校验 mode、section、answerType 和音频区间。
  • uploadPracticeAudio/uploadItemAudio：管理员、≤200MB、mp3/m4a/wav/ogg/webm/aac，再由 UploadStorage 落盘并写路径。
  • clearAdminSection → CetPaperHandler.clearSection；removePaper → deletePaper。前端 confirm 只是体验，安全仍由后端 requireAdmin。

7. AI Center 完整追踪

7.1 页面和附件

main.js 将 CHAT、AGENT、MULTI_WEB_AGENT 指向 AiRuntimeChatView.vue，由 route.meta.runtime 区分。设置来自 AiCenterSettings.vue/aiCenterSettings.js。send() 先调用 convert()：图片走 aiApi.analyzeVision()；文档走 aiApi.convertAttachment() → AiDocumentConversionService → MarkItDown Worker。

7.2 CHAT SSE 全链

AiRuntimeChatView.send → sendChat
→ chatApi.createSession → AiChatController.createSession → AiChatService.createSession(UUID)
→ chatApi.streamMessages POST text/event-stream
→ AiChatController.message: CurrentUser + SseEmitter(5min)
→ TraceContext.capture → virtual thread → AiChatService.answer
→ AiUsageGuardService.check
→ KnowledgeService.search（RAG）
→ RuntimeExecutionTraceStore.createExecution/createNode/transition
→ AiCredentialResolver.resolve
→ RuntimeProviderMatcher.match
→ ChatPromptBuilder + ChatHistoryStore.load(Redis)
→ RuntimeModelClientGateway.execute(primary + fallback)
→ Provider Client HTTP
→ SSE sources/delta/done 或 error
→ ChatHistoryStore.append + AiUsageGuardService.record
→ 前端 parseSse → assistant.content/sources/traceId
  • 限额：AiUsageGuardService.check() 使用 Redis 分钟/每日计数和 MySQL 月 token；管理员旁路，平台额度仅限制 PLATFORM。
  • RAG：KnowledgeService.search() 从知识源/Chunk 取候选，结合词法和 embedding 相似度排序。
  • 凭据：PLATFORM 查资格并解密平台 Key；STORED_BYOK 解密用户 Key；EPHEMERAL_BYOK 只存在请求内。
  • 匹配：RuntimeProviderMatcher.match() 从 Provider Repository 读取 Provider/Endpoint/Model/Capability，按能力、状态、优先级和成本排序。
  • 执行：LegacyRuntimeModelClientGateway.executeInternal() 调 Provider Client，记录 invocation、token、时延、成本和错误；可回退错误尝试候选。
  • 历史：ChatHistoryStore key=fc:chat:{user}:{session}，最多 20 条，TTL 120 分钟；Redis 故障降级为空历史。

7.3 AGENT

  1. sendAgent() 拼最近 12 条对话 → aiCenterApi.dispatch() → AiRuntimeDispatchController.start() → AiRuntimeDispatchService.start()。
  2. Service 写 ai_runtime_run、runKey、callbackToken；invokeAgent() 调 Gateway，可由 knowledgeContext() 加知识。
  3. Hermes 通过 ExternalAgentCallbackController 回调状态/产物；路径虽免登录拦截，但必须用每次 run 独立 Bearer callbackToken。
  4. 前端每 2 秒 dispatchRun()，watchdog 35 分钟；完成后 dispatchArtifacts() 与 artifact file。
  5. 产物 Controller 验证 run 属于用户，将路径 normalize 且必须在 uploads 根下，然后读 bytes；前端生成 Blob URL 并负责 revoke。

7.4 MULTI_WEB_AGENT

  1. 页面 PING 扩展，READY 后标记连接。
  2. dispatch providers=KIMI/DEEPSEEK/QWEN；seedParticipants() 写参与者。
  3. multiWebAssignments() 在明确分工时先让内部 Chat 产出 JSON；否则三方拿同一任务。
  4. window.postMessage(START_RUN) 给扩展；登录/验证码由用户完成。
  5. 扩展发 PARTICIPANT_STATUS；页面调用 reportParticipant()；后端 report() 推进 RUNNING/WAITING_LOGIN/SYNTHESIZING。
  6. BATCH 完成后 summarizeAndReview() 先总结再独立审核，以 phase=SYNTHESIS 写回。runKey 存 sessionStorage，刷新可恢复；取消会 DELETE dispatch 并发 STOP_RUN。

8. 分层、数据库、Redis 与文件

  • Controller：HTTP、状态码、序列化、multipart/stream。
  • Application Handler/Service：授权、校验、事务、跨仓储副作用。
  • Domain Repository interface：课程/Circle/CET 隔离业务与基础设施。
  • Jdbc Repository：参数化 SQL、行映射、冲突/不存在转换。
  • Shared：UploadStorage、认证授权、RequestContext、异常处理。

课程、Circle、CET、问题藤写方法以 @Transactional 保证数据库原子性。文件系统与数据库不是分布式事务：新增上传链必须设计数据库失败后的孤儿文件清理。Flyway 启动自动迁移；已发布 SQL 禁止改写，只新增版本。课程涉及 V1/V6/V15/V73，CET V11/V14/V63/V64，AI V25–V60，问题藤 V74/V75。

备份用 scripts/db-backup.sh（single-transaction、gzip、SHA-256）；演练用 db-restore-drill.sh 导入隔离库、核对表/Flyway/app_user 并自动删除。完整制度见 docs/数据库备份与恢复演练.md。

9. 部署、监控和排障

9.1 启动

  1. 复制 deploy/.env.example 为 .env，替换全部示例密码、加密 Key、Worker Token、URL/Origin。
  2. 启动 mysql、redis、markitdown-worker、pdf-renderer 并等待 healthy。
  3. 启动 backend；Flyway 和生产配置校验必须成功。
  4. 启动 frontend 或宿主机 Nginx；检查 /api/system/health。
  5. 按需启动 Agent Gateway 和绑定浏览器扩展。

后端日志在 /app/logs 的 volume；*.log/*.log.gz 不进 Git。Docker json-file 为 20MB×5；Alloy → Loki → Grafana。CI 执行前端测试/双前端构建、Maven、Worker pytest、空 MySQL Flyway migrate+validate，以及四个 Docker 镜像 Buildx。
